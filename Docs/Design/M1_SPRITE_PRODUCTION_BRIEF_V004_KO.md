# M1 캐릭터 스프라이트 제작 기획서 v004

## 0. 결정과 목적

기존의 대형 자동 생성 아틀라스는 더 이상 캐릭터 원본으로 사용하지 않는다. 모션마다 인물 크기, 활·망토·무기 돌출 길이가 달라 한 장의 시트에 억지로 맞추면 잘림, 발 위치 흔들림, 비일관적인 실루엣이 발생한다.

v004의 원칙은 다음과 같다.

1. 원본은 `캐릭터 × 모션 × 방향` 단위로 별도 제작한다.
2. 원본 그림의 크기를 맞추기 위해 신체를 늘리거나 자르지 않는다.
3. 최종 Unity 프레임만 공통 캔버스와 공통 발 피벗을 사용한다.
4. 캐릭터, 투사체, 마법 효과는 서로 분리한다. 활·화살·텔레그래프를 한 이미지에 합치지 않는다.
5. 코드의 역할은 검증·가져오기·재생뿐이다. 에셋의 구도나 크기를 코드가 보정하지 않는다.

이 문서는 새 에셋 제작의 단일 기준이다. 기존 v001~v003 PNG는 참고 자료일 뿐, v004 품질 기준을 만족하지 않으면 재사용하지 않는다.

## 1. 제작 우선순위

### P0 — M1 플레이 가능한 최소 캐스트

| ID | 역할 | 게임 내 기능 | 제작 우선도 |
|---|---|---|---|
| `player` | 축복술사 / 플레이어 | 이동, 대시, 축복 시전 | P0 |
| `dasher` | 돌진 기사 | 선형 돌진 텔레그래프와 근접 압박 | P0 |
| `archer` | 원거리 궁수 | 거리 유지, 조준, 화살 발사 | P0 |
| `minion` | 근접 추격자 | 느린 추격, 원형 근접 공격 | P0 |

M1 씬의 초기 배치는 플레이어 1명, Dasher 1명, Archer 2명, Minion 2명이다. 같은 적이 두 마리 등장해도 **색만 바꾼 복제본을 만들지 않는다**. 동일 종은 같은 고품질 원본을 공유하고, 적 개체 식별은 게임의 HP·위치·텔레그래프로 한다.

### P1 — M1 전투 보조 에셋

| 에셋 | 용도 | 캐릭터 본체와의 관계 |
|---|---|---|
| `arrow_projectile` | Archer 발사체 | 궁수 본체와 분리, 방향 회전 가능 |
| `dasher_line_telegraph` | Dasher 돌진 예고선 | 본체와 분리, 길이·폭은 코드에서 조절 |
| `archer_line_telegraph` | Archer 조준 예고선 | 본체와 분리 |
| `minion_circle_telegraph` | Minion 근접 범위 | 본체와 분리 |
| `hit_flash`, `death_burst` | 피격·사망 피드백 | 캐릭터 시트에 합성 금지 |
| `haste_cast`, `giant_cast` | 축복 시전 피드백 | Player 본체와 분리 |

### P2 — M2 이후 후보

M1 P0 검수와 실제 플레이테스트가 끝나기 전에는 제작하지 않는다. 후보는 고렘 보스, 최종 포털 수호체, 방 기믹 전용 소환체다. 새 몬스터는 먼저 아래의 캐릭터 카드와 모션 표를 채운 뒤 제작 승인을 받는다.

## 2. 공통 아트·크기 계약

### 화면상 실루엣

- 시점: 탑다운 3/4, 카메라를 향해 약간 남쪽을 보는 전투 시점.
- 최종 프레임: **128 × 128 px**, 투명 배경, Point 필터, 압축 없음.
- 일반 서 있는 캐릭터의 발바닥~머리 높이: **72 px ± 2 px**.
- 프레임 피벗: **(64, 116)**. 즉 발바닥 중심은 모든 프레임에서 같은 위치에 둔다.
- 안전 영역: 본체와 필수 무기가 `x=6..122`, `y=4..120` 안에 들어와야 한다.
- 예외: 사망 모션은 몸이 눕는 것을 허용하지만, 발 피벗과 캔버스 자체는 바꾸지 않는다.
- 배경, 체력바, 이펙트, 투사체, 그림자 효과를 캐릭터 PNG에 그리지 않는다.

### 원본과 최종 파일

| 단계 | 규격 | 목적 |
|---|---|---|
| 제작 원본 | 프레임당 256 × 256 px 이상, 투명 PNG | 세부 묘사와 여백을 충분히 확보 |
| 검수본 | 방향·모션별 개별 프레임 PNG | 크기·발 위치·실루엣 승인 |
| Unity 최종본 | 프레임당 128 × 128 px | 공통 피벗을 적용한 런타임 사용본 |
| Unity 스트립 | 한 파일 = 한 캐릭터·한 모션·한 방향 | 최대 `6 × 128 = 768 px` 폭, 128 px 높이 |

**금지:** 4096px 이상 가로 시트, 모든 방향을 한 PNG에 넣는 시트, 타 캐릭터 프레임이 섞인 시트, 초록색 크로마 배경, 프레임마다 달라지는 캔버스 크기.

### 방향 규칙

기본 납품은 8방향이다.

`South`, `SouthEast`, `East`, `NorthEast`, `North`, `NorthWest`, `West`, `SouthWest`

- 좌우 비대칭 장비(활, 망토 문양, 방패, 화살통)가 있는 캐릭터는 8방향을 직접 제작한다.
- 대칭 캐릭터만 아트 디렉터 승인 후 `SouthEast/East/NorthEast`의 좌우 반전을 `SouthWest/West/NorthWest`에 사용할 수 있다.
- `North`는 South 프레임을 뒤집거나 색만 어둡게 만든 그림을 쓰지 않는다. 머리·망토·등 장비의 후면 정보를 가진 별도 실루엣이어야 한다.

## 3. 캐릭터 카드

### Player — 축복술사

- 실루엣: 짧은 외투, 한 손은 축복 문양을 만들고 다른 손은 이동 균형을 잡는다.
- 전투 인상: 직접 공격하지 않고, 위험 지역을 이동·대시로 통과하며 적에게 축복을 부여한다.
- 구별점: 망토 끝의 청록색 포인트와 손 주변의 작은 룬. 룬은 별도 VFX로도 읽혀야 한다.
- 금지: 검·총·활처럼 직접 공격자로 오해될 무기, 과도한 후광, HUD에 가까운 아이콘.

### Dasher — 돌진 기사

- 실루엣: 넓은 어깨, 무거운 장화, 전방으로 기울어진 장창 또는 돌진용 무기.
- 전투 인상: 멈춰서 노려본 뒤 한 줄로 강하게 돌진한다.
- 구별점: 장창의 전방 축, 짧고 무거운 망토, 낮은 자세. Archer와 같은 후드 실루엣을 금지한다.
- 공격 본체 범위는 별도 텔레그래프가 담당한다. 돌진 궤적을 캐릭터 프레임에 길게 그리지 않는다.

### Archer — 원거리 궁수

- 실루엣: 비대칭 활, 화살통, 가벼운 망토. 활의 외곽선만으로도 Dasher와 구분되어야 한다.
- 전투 인상: 거리를 유지하다가 몸을 멈추고, 당기고, 발사하고, 균형을 회복한다.
- 구별점: 조준 때 팔·활·시선이 모두 목표 방향을 가리킨다. 발사 순간의 활시위와 몸통 회전을 명확히 분리한다.
- 화살, 비행 잔상, 명중 효과는 별도 에셋이다. 본체 프레임에 화살 궤적을 넣지 않는다.

### Minion — 근접 추격자

- 실루엣: 낮은 키, 큰 소매 또는 손, 가벼운 후드. Player보다 작고 Dasher보다 훨씬 가벼워야 한다.
- 전투 인상: 불규칙하게 접근하지만, 공격 순간에는 짧고 선명하게 몸을 내민다.
- 구별점: 빠른 작은 보폭, 넓은 팔 동작, 둥근 근접 공격 자세.
- 금지: Archer처럼 활·긴 막대·화살통이 보이는 장비, Dasher처럼 긴 직선 무기.

```text
Assets/_Project/Art/M1Production/Characters/Animation/MotionsV004/
  chr_<role>_<state>_<direction>_motion_v004.png
```

예시:

```text

```

이 파일은 `128 × (프레임 수)` 크기의 가로 스트립이다. 예를 들어 Archer의 `attack_execute`는 `768 × 128 px`이다. 다른 방향·상태·캐릭터의 프레임을 넣지 않는다.

## 6. 제작·검수 순서

1. **캐릭터 카드 승인:** 각 캐릭터의 South `idle` 4프레임만 먼저 만든다.
2. **크기 게이트:** 72px 높이, `(64,116)` 발 피벗, 안전 영역, 다른 캐릭터와의 상대 크기를 검수한다.
3. **방향 게이트:** 8방향 `idle`을 모두 제작해 장비·망토·활의 방향이 설득력 있는지 검수한다.
4. **이동 게이트:** `walk`, `run` 루프를 제작하고 GIF 또는 영상으로 발 미끄러짐을 검사한다.
5. **전투 게이트:** `attack_charge → attack_execute → recover`를 연속 재생해 준비·발사/돌진·회복이 한 동작으로 읽히는지 검사한다.
6. **피격·사망 게이트:** `hit`, `death`가 피벗과 캐릭터 식별성을 유지하는지 검사한다.
7. **Unity 임포트 게이트:** 개별 스트립의 Sprite 분할, 피벗, Point 필터, 투명도, 실제 씬의 크기·정렬을 확인한다.
8. **플레이 게이트:** Player 1, Dasher 1, Archer 2, Minion 2가 동시에 보이는 M1 장면에서 최소 30초 관찰한다.

다음 경우에는 수정 보정이 아니라 원본 재제작으로 되돌린다.

- 활·망토·무기·머리·발이 한 프레임이라도 잘림
- 프레임마다 발바닥이 위아래로 튐
- North/대각선에서 캐릭터 역할이 알아보기 어려움
- 공격 준비와 발사·돌진 순간을 구별할 수 없음
- 다른 캐릭터의 외곽선·색·장비와 혼동됨

## 7. 생성 요청 템플릿

```text
2D top-down 3/4 pixel-art game sprite, transparent background.
Character: <role and character-card summary>.
Motion: <state>. Direction: <direction>. Frame <index> of <count>.
Keep the feet centered at the same baseline; target standing silhouette height is 72 px after final 128x128 export.
No background, UI, shadow, projectile trail, text, border, cropped weapon, or other characters.
Keep weapon and cloak fully inside the frame with generous transparent margin.
Use the approved violet-blue M1 palette and a crisp readable silhouette.
```

생성기는 한 번에 여러 모션·여러 방향·여러 캐릭터를 섞어 요청하지 않는다. 요청 한 건은 하나의 `role/state/direction/frame`만 다룬다.
